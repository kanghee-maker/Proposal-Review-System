# 제안 자료 재연결 결과

2026-10-28 기준 GitHub 최신 `main`의 기준 엑셀 134건에 맞춰 부서별 제안서를 반영했습니다.

- 게시판 번호와 제안자를 교차 확인하고, 실제 작성 시트의 제안명을 파일명과 대조했습니다.
- 목록 제목은 기준 엑셀을 그대로 유지했습니다. 원본 제안서의 제목 표현 차이는 `proposal-source-manifest.json`의 `source_title`로 확인할 수 있습니다.
- 제안서 134개, 보충자료 18개를 `public/proposal-sources`에 부서별로 배치했습니다. 원본 바이트는 변경하지 않았습니다.
- Excel 내부의 사진·도표·추가 시트는 원본 다운로드로 확인할 수 있습니다. 본문은 실제 작성 시트에서 추출하며 공통 예시를 사용하지 않습니다. 실제 작성 내용이 ‘제안 예시’라는 이름의 시트에 들어 있는 경우에는 제목·제안자를 확인해 해당 시트를 선택합니다.
- 150번과 152번은 파일명과 내부 제목에 표현 차이가 있으나 게시판 번호·제안자·제안 주제를 대조해 확인했습니다. 확정하지 못한 연결은 없습니다.
- 사용자가 중복으로 지정한 8건은 새 자료에 포함하지 않고 조회에서도 제외합니다. 과거 Git 이력은 변경하지 않습니다.
- 게시판 번호와 제안자로 연결하므로 회차별 연번 변경이나 1차 심사 복제 후에도 올바른 원본을 사용합니다. 사용자 업로드, 부서 배정, 평가 결과는 유지합니다.

## 검증

- 기준 엑셀 134건과 데이터의 게시판 번호·제목·제안자 일치 확인.
- 원본 및 복사본 152개의 SHA-256·크기 검증.
- 실제 HTTP 다운로드 API로 152개 파일을 받아 해시 일치 확인.
- 회차별 연번 변경, 잘못된 제안자 차단, 기존 사용자 첨부 보존, 평가·배정 상태 보존, 중복 8건 제외 회귀 검사 통과.
- TypeScript 검사 및 Next.js 프로덕션 빌드 통과. 운영 Supabase와 분리된 로컬 환경에서 검증했습니다.

## 운영 반영

GitHub 변경을 배포한 뒤 기존 회차를 열면 자료 카탈로그가 오래된 DB 본문·기본 첨부 연결을 보정합니다. 운영 DB에 직접 쓰는 작업은 하지 않았습니다.

과거 `public/default-attachments`와 오래된 목록 사본은 일괄 삭제 승인이 거절되어 유지합니다. 새 카탈로그에서 사용하지 않으며, 해당 레거시 파일의 영구 정리는 별도 확인이 필요합니다.

재검증: `node scripts/verify_proposal_sources.cjs`

재수집: Python의 openpyxl을 설치한 환경에서 `python scripts/reconcile_proposals.py "부서별 원본 폴더" --repo .`를 실행합니다. 실행 전 최신 기준 엑셀과 134건 목록을 확인해야 합니다.
